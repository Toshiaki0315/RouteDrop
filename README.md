# RouteDrop

落ちゲー × オートマトン。落ちてくるパネル（直進 / 右折 / 左折）を積んで列車の進路を作り、目的地の駅まで走らせるパズルゲーム。Tauri v2 (Rust + React/TypeScript) 製の macOS デスクトップアプリ。

## ルール

目的は、列車を **次々と駅へ導いて** できるだけ遠くまで走らせること。駅に着いたら、そこから次の駅までまたレールをつないでいく（終わりはなく、ゲームオーバーまで続く）。

- 盤面は 7×12 の草地。**始発駅は盤面の最下段の中央**にあり、列車はここから北向きに出発する。始発駅は駅舎のアイコンで描かれ、他の駅と同じ駅のマスとして列車が通り抜けられ、落下パネルは上に積める。
- **駅は、最初は始発駅から縦に 15 マス先**にある（列はランダム）。盤面は 12 段しかないので、駅は最初は盤面の上にはみ出していて見えない。
- 駅に着くたびに、次の駅までの距離は **20 → 25 → 30 → …** と 5 マスずつ遠くなる（直前の駅から縦に数える。列はランダム）。画面上部の「次の駅まで」に残りの距離が出る。
- 落下するのはレール。種類は直進・右折・左折の 3 つでランダム、出現する列もランダム。次に降るレールと出現する列は、左上のアイコンとフィールド上端の ▼ で分かる。
- レールは 2 つの端をつなぐ。Space で時計回りに 90° 回せる。
  - 向きが北のとき、直進は 南↔北、右折は 南↔東、左折は 南↔西 をつなぐ。
- 列車 (SL) は 0.5 秒ごとに正面へ 1 マス進む。
  - 正面が **レール**: つながっている端から入って、反対の端へ抜ける（逆向きからも通れるが、引き返すことはできない）。
  - 正面が **つながっていない辺のレール**: 脱線してゲームオーバー。
  - 正面が **空きマス**: その場で待機する（つながるレールが落ちてくるかもしれない）。
  - 正面が **駅**: 到着（+100 点）。駅は向きを変えずそのまま通り抜けられ、先へレールをつなげる。
  - 正面が **盤面の外・壁**: ゲームオーバー。
- 落下パネルは 1 秒ごとに 1 マス落ち、着地するとレールとして盤面に固定される。駅のマスには入れない（駅の上には積める）。
- **ライン消去**: 列車より下（通過済み）の行がすべてレール（か駅）で埋まると、その行が消えて +50 点。
  消えた行より上のもの（レール・駅・列車）は 1 段下がる。これで盤面の上にはみ出していた駅が少しずつ見えてくる。
  始発駅も「埋まり」として数えられ、列車が出発して行より上へ進んだあとは、始発駅の行も他の行と同じように消える。
  列車のいる行とそれより上は消えない。
- **列車が一番下の行にいて、その行がすべて埋まったらゲームオーバー**（その行は消せないため。出発前の始発駅の行も同じ）。
- パネルは最上段の空いている列からランダムに出現する（駅や積み上がったレールのある列は避ける）。最上段がすべて埋まったらゲームオーバー。

## 画面

1 マスは 48×48 ピクセル。レール・駅・列車はパステル調のイラストで、Canvas で描画している。

- 画面上部の 1 行に `Score / 到着駅 / 次の駅まで` を表示する（ゼロ埋め）。
- 次に降ってくるレールは、左上のアイコンに表示し、アイコンの下に「次のレール」と書く。出現する列は前もって決まっていて、フィールド上端の ▼ とその列の最上段のうすい色で示す（その列が埋まっていたら、空いている列から選び直す）。
- ゲームオーバーになると、フィールドの真ん中に「GAME OVER」と「Restart」ボタンが出る。**Enter キーか Space キーでも Restart できる**（ゲームオーバーの直後 0.5 秒は、連打中のキーで誤ってリスタートしないよう無視する。押しっぱなしも無視）。

## 操作

| キー | 動作 |
| --- | --- |
| ← / → (A / D) | 移動 |
| Space | パネルを時計回りに 90° 回転 |
| ↓ (S) | ソフトドロップ |
| ↑ (W) | ハードドロップ |

## 構成

- `src-tauri/src/core/` — 純粋なゲームロジック (Rust)。UI/Tauri 非依存、カバレッジ 100% 維持。
- `src-tauri/src/commands.rs` — Tauri Command (`new_game` / `get_state` / `send_input` / `tick`)。
- `src/` — 描画と入力のみ (TypeScript / React / Canvas)。ロジックは持たない。

## 開発

`make` で一覧が出る（OboeGaki と同じ流儀）。

```bash
make setup      # 初回セットアップ（npm install）
make dev        # 開発起動（Tauri dev。初回は Rust ビルドで数分）
make app        # アプリ (.app) を組む → src-tauri/target/release/bundle/macos/RouteDrop.app
make dmg        # インストール用 DMG を組む → src-tauri/target/release/bundle/dmg/
make test       # フロントエンド (Vitest)
make test-rust  # Rust (cargo test)
make coverage   # カバレッジ計測 (TS と Rust の core。core は 100% 必須)
make check      # コミット前チェック（型 + 全テスト + core カバレッジ 100%）
```

- dev サーバのポートは既定 1430（1420 は他の Tauri アプリと衝突しやすい）。`ROUTEDROP_DEV_PORT=1500 make dev` で変えられる。
- `.app` / DMG はまだ署名・公証していない。初回は右クリック →「開く」で Gatekeeper を通す。

開発ルールは [.agent/tdd-rules.md](.agent/tdd-rules.md) を参照 (TDD: Red → Green → Refactor)。
